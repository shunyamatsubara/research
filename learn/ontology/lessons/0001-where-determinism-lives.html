Lesson 1 · about 12 minutes

Where determinism lives

When a vendor says its AI agent makes deterministic decisions from messy documents, the claim is usually true for one half of the system and not for the other. This lesson teaches you to see the two halves.

Why this matters for your mission. In every demo of an “ontology + agent” product, something messy goes in (a scanned form, a doctor’s note, an email) and a decision comes out. Your first question as a judge is always the same: which part makes the decision, and can that part give a different answer next time?

Two halves and a contract

A language model reads. Rules decide. The ontology is the contract between them.

The read step turns unstructured input into typed facts, such as procedure: MRI_Knee. A language model is very good at this, but it is not deterministic. Even with the temperature setting at 0, the same input can come back with a different output.11Anthropic’s docs: “Even with temperature set to 0, the results will not be fully deterministic and identical inputs may produce different outputs across API calls.” Anthropic glossary. In one test, 1,000 runs of the same prompt at temperature 0 gave 80 different completions. Thinking Machines Lab, 2025

The decide step takes typed facts and applies fixed rules, for example a decision table. This is ordinary code. With the same facts and the same rule version, it gives the same answer every time, and it can show which rule produced the answer.22The industry standard for rule tables, OMG DMN, defines a decision table as “a tabular representation of a set of related input and output expressions, organized into rules indicating which output entry applies to a specific set of input entries.” OMG DMN 1.6, §8.1

The ontology sits in the middle. It says which kinds of things exist (Procedure, Diagnosis, Member), what fields they have, and how the kinds relate, such as MRI_Knee is-a AdvancedImaging. It is a contract: the reader may only produce these kinds of facts, and the rules may only talk about these kinds of facts.33The classic definition: “An ontology is an explicit specification of a conceptualization.” Gruber, 1993. Palantir says its Ontology holds “semantic elements (objects, properties, links) and kinetic elements (actions, functions, dynamic security)”. Palantir docs

Put together: the decision is deterministic given the facts. It is not deterministic given the input. When a vendor says “deterministic”, they almost always mean the second half. Ask how they control the first. Palantir’s own docs agree: deterministic functions “complement the non-deterministic reasoning of LLMs”.44Palantir docs, “Why create an Ontology?”

Try it: one note, many decisions

The simulator uses a simplified rule for approving a knee MRI. I made it up for this lesson, in the style of real coverage rules.55Real rules have the same shape. A Medicare billing article lists the diagnosis codes that “support the medical necessity of CPT code 82306”, a vitamin D blood test; every code not on the list fails. CMS Coverage Database, Article A57718. Japan publishes the same kind of table: its check master lists the disease names that make that test valid. DX審査支払機構, コンピュータチェックに関する公開 Press Run the reader five or six times and watch the run log. Then change a fact by hand.

What to notice

  1. Same facts, same decision. Every time the facts matched, the decision matched. That is the deterministic half doing its job.
  2. Same note, different decisions. The note is unclear: a fall and a swollen knee may or may not count as a red flag. The reader settled that question differently on different runs. No rule table can remove unclearness that lives in the input.
  3. A silent wrong link. In one reading, the reader linked “MRI, right knee” to the general class Imaging instead of MRI_Knee. The rules for advanced imaging then never looked at the claim, and row R4 approved it. Choosing the wrong class in the ontology is also a reading error, and nothing in the table can see it.
  4. The table never says “deny”. It only approves or sends the claim to a person. Real systems are moving the same way. Since 2025, California law says a denial based on medical necessity “must be reviewed and decided by a licensed physician”.66California SB 1120, the “Physicians Make Decisions Act”, in effect from 1 January 2025. Senator Becker’s office Japan’s claim-review body says its computer checks are not applied mechanically as the final judgment.77「コンピュータチェックは、診療内容の適否について、画一的あるいは一律的に適用するものではない。」 DX審査支払機構 (the former 支払基金, renamed on 1 October 2026) Rules can be deterministic and still not be allowed the last word.

How is-a lets one rule cover many cases

You already know the chair example: chair is-a furniture is-a object. The same idea does real work in a decision system. Rows R1 to R3 never mention MRI. They talk about AdvancedImaging. The ontology says MRI_Knee is-a AdvancedImaging, so the rows apply to it. If you add CT_Knee is-a AdvancedImaging tomorrow, the same rows cover knee CT claims with no new rule.88“A class A is a subclass of B if every instance of A is also an instance of B”, and “all subclasses of a class inherit the slot of that class.” Noy & McGuinness, Ontology Development 101. The link must be written down: it “cannot be derived from the labels”. W3C OWL 2 Primer, §4.2

This is the main gift an ontology gives the deciding step: write a rule once, at the general level, and it reaches every more specific kind. It also shows the main risk: the rules only ever see the class the reader picked. Lesson 2 looks at what an ontology adds beyond a plain data schema.

Primary source to read next

“Building effective agents”, Anthropic, December 2024. About 20 minutes. It separates workflows (“LLMs and tools are orchestrated through predefined code paths”) from agents (the model directs its own steps). Read the first two sections and the part on prompt chaining with a “gate”. As you read, ask: in a vendor’s product, which parts are predefined code paths? That is where determinism can live.
