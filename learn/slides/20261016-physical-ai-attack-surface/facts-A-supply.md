# Facts, angle A (mechanism): the model and data supply chain of a tier-1 supplier

Collected 2026-10-16 for the question: when a learned model decides what a robot arm, an AMR or a car does, where can an attacker get in, and which existing controls can see each way in. This file covers one sub-topic: how a model gets into a deployed robot or ECU, and where each step crosses an organisational boundary.

## How to read this file

- Tags in the notes column say where a row lands for a supplier: [factory], [product], [supply-chain], [general].
- Every number or key claim has its quote in the notes. All pages were read with the WebFetch tool, which returns a small model's extraction of the page, not the raw page. I put text in quotation marks only when the tool returned it in quotation marks, or (NIST AI 100-2 E2025, HF pickle page, Transformers docs) when I had the full text. Where the tool gave a paraphrase I say "paraphrase". Treat quotes as "as returned by the tool", not as byte-exact.
- Pages carry no date unless I give one. "undated" means the page shows no date; the content was current on 2026-10-16 when fetched.
- Discovery by web search was not possible: the search budget shared by all agents was used up before my first query returned. Every source below is a URL I already knew and fetched directly. Coverage of Bosch, Denso and Japanese sources is therefore weak (see the last section).
- The step list and the format cheat-sheet are my composition from the rows. They are not quoted from any one source.
- Fact-checked 2026-10-16 (see verify-A-supply.md): every row was re-read against its source. Corrected and replaced-source rows say so at the end of their notes. github.com pages were blocked in the checking environment, so GitHub READMEs were read from raw.githubusercontent.com and GitHub advisory pages through WebFetch, cross-checked against api.osv.dev.

## The chain as a numbered sequence (my composition; row ids in brackets)

1. **Base components are trained by big labs and released openly.** A language model (Llama 2, Meta) and vision encoders (DINOv2, SigLIP) are trained on web-scale text and curated image sets. Boundary crossed: big-tech lab to open-source community. [A501, A503]
2. **Robot-learning labs and platform vendors stack these into a robot policy (a VLA) and pool robot data.** OpenVLA = Llama 2 + DINOv2 + SigLIP, trained on Open X-Embodiment (pooled from dozens of labs). NVIDIA GR00T and Alpamayo, Physical Intelligence pi0 are comparable releases. Boundary: academic labs and vendors to public hubs (Hugging Face, GitHub, GCS buckets, NVIDIA NGC), each with its own licence. [A502-A512]
3. **The supplier's ML team pulls model, code and data from the hub.** Calls such as `from_pretrained`, `torch.load`, `gsutil cp`, the NGC CLI. The same call can fetch weights (data) and Python code (executed). Boundary: open-source community / cloud hub to the supplier's dev environment. [A513, A514, A533-A547]
4. **Own data is collected and labelled.** Teleoperated demonstrations in a plant cell, test-drive or fleet data from vehicles, then labels from a labelling vendor or from an automatic VLM labeller. Boundary: supplier to labelling vendor (and, for vehicle data, OEM / vehicle owner). [A515, A518, A519, A512, A520]
5. **Synthetic data and simulation fill gaps.** Isaac Sim / Omniverse / Cosmos generate trajectories and sensor data; the generator is itself a third-party model with its own licence. Boundary: supplier to platform vendor (NVIDIA) and cloud. [A508, A520, A521]
6. **Fine-tuning.** LoRA on one workstation GPU (about 22.5 to 27 GB of memory) up to full fine-tuning on one 80 GB GPU (openpi) or a node of 8 x A100 (OpenVLA's example); done in-house, by a contractor, or on a cloud. Backdoors planted upstream are reported to survive this step. Boundary: supplier to cloud / contractor if training is outsourced. [A524-A530]
7. **Export and compile for the edge.** Weights go to safetensors / ONNX, then to a TensorRT engine ("plan") built for one GPU type and one TensorRT version; plugin libraries may be added. Boundary: supplier CI to NVIDIA toolchain (a tier-2 software supplier). [A548-A550]
8. **Sign and describe the artefact (optional today).** OpenSSF model signing (Sigstore), NGC signatures, AI-BOM (CycloneDX ML-BOM, SPDX 3 AI profile). A signature proves "unchanged since signed by X", not "safe". Boundary: supplier to downstream consumer (OEM, plant, integrator). [A534, A554-A557]
9. **Ship to the device.** Robots / AMRs: image or package update to a Jetson-class computer through the vendor's own OTA, apt or containers. Vehicles: the model is part of ECU software handed to the OEM, who pushes it through the OEM's OTA back end (Uptane-style metadata, UN R156 update management). Boundary: supplier to OEM (vehicles) or to plant / integrator / end customer (robots). [A551-A553, A558, A559, A560]
10. **Load at runtime.** The device deserialises the engine or weights; a TensorRT plan is an executable artefact and plugin libraries are native code. [A548, A549]
11. **Fleet or robot data goes back.** Selected drives or episodes are uploaded for mapping or retraining (REM, openpilot, NVIDIA's reconstruct-and-simulate flow), which re-enters at step 4. Boundary: vehicle owner / OEM / supplier / labelling vendor. [A521-A523]
12. **Retrain and ship again.** Each loop re-runs steps 3-9, so each loop re-crosses the same boundaries.

## Format cheat-sheet: what each artefact can do when it is loaded (my summary of the rows)

| artefact | executes code on load? | what the rows say | rows |
|---|---|---|---|
| Python pickle (`.pt`, `.bin` from older `torch.save`) | yes, by design | opcodes `GLOBAL` / `REDUCE` import and call functions; Hub scanners are "not 100% foolproof" | A533, A534, A545, A546 |
| `torch.load` with `weights_only=True` | restricted, but bypassed in torch 2.5.1 and earlier | default became True in 2.6; RCE advisory against 2.5.1 and earlier | A535, A536 |
| Hub repo with custom code (`trust_remote_code=True`) | yes, Python from the repo | docs advise pinning a commit hash | A537, A503 |
| safetensors | no (tensors only); audited, no critical code-execution flaw found | weights can still carry a backdoor | A538, A539 |
| Keras v3 `.keras` | only if `safe_mode=False` (Lambda) | default True | A540 |
| ONNX protobuf | no code by itself; loader bugs and external-data file reads reported 2026; custom-op `.so` loads only if the application registers it | graph can hold a no-code backdoor (ShadowLogic) | A541, A542, A543, A530 |
| TensorRT plan | treated as executable by NVIDIA | version-compatible plans embed a runtime; plugins are native libraries | A548, A549 |
