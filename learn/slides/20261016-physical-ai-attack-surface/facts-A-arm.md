# facts-A-arm: how a learned model drives an industrial robot arm or cobot (angle A, mechanism)

Compiled 2026-10-16. Scope: sensor-to-motor sequence for an AI-controlled arm; Denso Wave, Bosch Rexroth/Kassow, public Bosch and Denso AI-robot work. Only brief.md was read in this folder.

How to read: statements are facts; interpretation is kept in the notes column and marked "Interpretation:". Every number or key claim has its exact quote in notes. Tags show where the fact lands for a supplier: [factory], [product], [supply-chain], [general]. "PDF text read" means I downloaded the PDF and read the extracted text; "page text read" means I read the page text, not a search snippet. Reliability: primary = author's own paper, vendor's own documentation or press release, standards body; secondary = trade press, vendor commentary on a standard, reseller mirror of a catalogue; hearsay = none used.

Rates are the published ones for the named system; they differ by model and robot. The Denso rows describe the route a learned model would take into a Denso controller (b-CAP Slave Mode); no source I read says a VLA is deployed on that route.

## Steps popular explanations skip (each with the row that shows it)

1. Pre-processing and de-normalisation with dataset statistics (A13, A20): the output only means something with the training set's quantiles.
2. A fixed-size action vector padded to the largest robot (A18).
3. Action chunks run open loop for 0.5 to 0.8 s before the model looks again (A17).
4. A network hop and a separate decoder to hide latency (A12, A14, A16, A22).
5. A position loop below the model (PD/PID) that simply tracks targets, with no collision check in the research stacks (A6, A21).
6. The controller's own acceptance rules: rights by path, TCP without check code, speed/acceleration limits, buffer underflow errors (A35-A38).
7. The robot's own real-time layer between pose and motor (A39).
8. Depth and force are mostly handled outside the VLA, by vision pipelines and controller functions (A7, A8, A29).
9. The safety function is built from axis, speed, position and torque monitors and safety I/O, rated PL d Cat. 3, and does not look at images or instructions (A40, A49, A51). Whether the tool, workpiece and limits suit a learned policy is settled in the risk assessment (A50).
10. Standards: TR 5469 names "non-AI safety related functions" as the way to make AI-controlled equipment safe (A55); the EU Machinery Regulation singles out ML that ensures safety functions (A57).
11. For LLM planners the model output is a skill call or code, so the skill library and code runner are the real command path (A25-A28, A32).
