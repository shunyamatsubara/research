求めた (0.10, 0.15, 0.75) m は、カメラから見た数字だ。これを motion planning にそのまま渡すと、土台の原点から 10 cm、15 cm、75 cm の場所を目指す。物体はそこにないので、腕は別の場所へ動く。だから土台から見た数字に直す必要がある。

そのために「座標系（frame）」を決めておく。座標系とは、数字を測るための物差しの組で、原点（数字がすべて 0 になる点）が 1 つと、x, y, z の 3 本の軸の向きでできている。点の数字は「原点から、各軸に沿って何 m 進んだか」だから、どの座標系で測るかで変わる。土台にもカメラにも、それぞれの座標系がある。

toy では、同じ点がこう書ける。カメラの座標系では (0.10, 0.15, 0.75)、土台の座標系では (0.60, −0.15, 0.05) だ。点は動いていない。測る原点と軸が違うだけである。ここでも toy の偶然がある。カメラは土台の x 方向に 0.5 m、高さ 0.8 m の位置で、真下を向いている。だから軸の向きは符号が変わるだけで済む。

![Figure 3](#fig-3) — 左は土台の座標系の中のカメラ。位置 (0.5, 0, 0.8) に 3 本の軸を描き、カメラの x 軸に 0.10、y 軸に 0.15、z 軸に 0.75 歩いて (0.60, −0.15, 0.05) に着く。右は 4x4 で、列ごとに色分けしてある。強調は z = 0.05。

図 3 の左を見てほしい。カメラの x 軸は土台の +x、y 軸は土台の −y、z 軸は土台の −z（真下）を向いている。計算は「カメラの原点から出発し、カメラの 3 本の軸に沿って歩く」ことだ。土台の数字で書くと、次の 3 つになる。
- x = 0.5 + 1 × 0.10 = 0.60
- y = 0 + (−1) × 0.15 = −0.15
- z = 0.8 + (−1) × 0.75 = 0.05

z = 0.05 は、机の上 5 cm の物体の上面の高さと合っている。

この歩き方を 1 つの表にまとめたのが「4x4 同次変換」だ。図 3 の右を見ると、1 列目 (1, 0, 0) はカメラの x 軸が土台の数字でどう見えるか、2 列目 (0, −1, 0) は y 軸、3 列目 (0, 0, −1) は z 軸を表す。4 列目 (0.5, 0, 0.8) は、カメラの原点が土台のどこにあるかだ。

この表に点を掛ける手順を、一度だけ具体的に書く。点を (0.10, 0.15, 0.75, 1) と 4 つの数にして、表の各行と、同じ位置どうしを掛けて全部足す。1 行目は 1 × 0.10 + 0 × 0.15 + 0 × 0.75 + 0.5 × 1 = 0.60 で、土台の x になる。2 行目は 0 + (−1) × 0.15 + 0 + 0 = −0.15、3 行目は 0 + 0 + (−1) × 0.75 + 0.8 × 1 = 0.05 だ。4 行目 (0, 0, 0, 1) は 1 になり、答えの最後の数が 1 のまま残る。

では、なぜ点に 1 を足すのか。軸に沿って歩く部分は掛け算で、出発点を足す部分は足し算だ。点の最後に 1 を付けると、4 列目に 1 が掛かり、足し算も掛け算の中に入る。だから 1 回の掛け算で、軸の向きと出発点が同時に済む。

この表を T_base_cam と書く。読み方は「土台から見たカメラの姿勢」で、使い方は「カメラの数字を土台の数字に直す表」だ。「外部パラメータ（extrinsics）」とも呼ぶ。形は、順運動学（FK）で出す T_base_ee と同じだ。T_base_ee は、手先（ee）の原点と軸を土台から見た表で、T_base_cam はその手先をカメラに替えたものである。

最後に落とし穴が 1 つある。この記事のカメラの軸は x が右、y が下、z が前方で、これを optical frame と呼ぶ。ROS のロボット本体の軸は x が前方、y が左、z が上で、camera_link はこちらに従う。2 つは向きが違うので、camera_link の姿勢をこの計算に使うなら、先に固定の回転で軸をそろえる。
