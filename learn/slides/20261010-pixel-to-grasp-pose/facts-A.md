| A7 | RealSense deprojection uses x = (u - ppx)/fx, y = (v - ppy)/fy, then point = (depth*x, depth*y, depth). | https://github.com/IntelRealSense/librealsense/blob/master/src/rs.cpp (`rs2_deproject_pixel_to_point`, ~line 4387; output lines `point[0] = depth * x; point[1] = depth * y;`) | fetched 2026-10-10 | primary (code) | Equivalent to X = (u-cx)Z/fx, Y = (v-cy)Z/fy, Z = depth. ## Part 2: pipeline as numbered steps

Notation: T_ab is a 4x4 transform taking points in frame b into frame a. Quantities marked [mine] are my formulation.

0. Inputs: RGB (W_c x H_c x 3), raw depth uint16 (W_d x H_d), text instruction, K_c and K_d, depth scale (m/unit), the extrinsic T_base_cam (eye-to-hand: constant; eye-in-hand: T_base_gripper(q at capture) * T_gripper_cam), TCP offset T_flange_tcp.
1. Resize and send: the VLM sees a resized or padded image (e.g. Molmo's 336 px input per A3). The coordinates it returns refer to the original image if the model normalizes (A1-A3). Keep (W_c, H_c) of the image you sent.
2. Parse the VLM output: points, boxes or mask. Gemini [y,x]/0-1000, boxes [ymin,xmin,ymax,xmax]/0-1000, Molmo x,y percent (A1-A4). Mask: from SAM or LangSam; OK-Robot uses it for filtering (A24).
3. Convert to pixels: u = x_norm/1000 * W_c; v = y_norm/1000 * H_c (Gemini). For Molmo: u = x/100 * W_c. For a box, take the mask or the center plus an inner shrink [mine]. Output: float (u, v) in color pixels.
4. Align depth to color (A11): same viewpoint and resolution. If not aligned, scale K by the resolution ratio (A6) AND apply the depth-to-color extrinsic; otherwise u,v index the wrong depth pixel.
5. Pick depth Z (m): Z = raw * depth_scale. Reject 0 (A12). For a point: use a small window median of valid depths [mine]. For a mask: median of valid depths inside the (eroded) mask [mine].
6. Undistort (if the model has non-zero coeffs) then back-project (A5, A7, A8): x' = (u-cx)/fx, y' = (v-cy)/fy, X_c = x' Z, Y_c = y' Z, Z_c = Z. Output: 3D point in the camera optical frame, meters.
7. Surface normal / orientation. Options: (a) heuristic top-down: z axis of the gripper = -z_base; yaw from PCA of the mask's points projected to the table plane [mine]; (b) normal estimated from the local point cloud [mine]; (c) a grasp network on the cropped cloud (AnyGrasp, Contact-GraspNet) then choose the grasp whose center lands inside the VLM mask or nearest the VLM point (A13, A15, A20, A24). Output: R_cam_grasp (3x3), centre p.
8. Frame fix: optical (z forward) -> robot-style axes if you use ROS tf (A18), then T_base_grasp = T_base_cam * T_cam_grasp. T_base_cam comes from hand-eye calibration (A16, A17) and, for eye-in-hand, from forward kinematics at the capture time.
9. Gripper convention: define the grasp frame with the approach axis (usually z of the TCP). Match the network's gripper-frame convention to your robot's TCP [mine]; apply flange offset: T_base_flange = T_base_grasp * (T_flange_tcp)^-1 [mine].
10. Pre-grasp: T_base_pre = T_base_grasp * Trans(0,0,-d) in the grasp frame, with d about 5-10 cm [mine; OK-Robot has a "simple pre-grasp approach" (A27)]. Output: two 4x4 poses for the planner.
11. Validate: reachability, IK, collision with the point cloud; reproject a gripper marker into the image to sanity-check [mine].

## Part 3: where the error comes from (by stage)

- VLM localization error (step 2): not geometric; the point may sit on background or between objects. Not in any source I read; measured accuracy numbers were not found.
- Coordinate conventions and resize (steps 1-3): wrong axis order or scale gives errors of tens to hundreds of pixels (A1-A4).
- Depth sensing (step 5): holes, noise, edge flying pixels. A point on an object edge can take the background depth [mine]. Depth error scales with distance for stereo [mine].
- Alignment and intrinsics (steps 4, 6): misalignment shifts the depth lookup; neglected distortion error grows toward the edges (A8).
- Extrinsics (step 8): hand-eye error is rotation-sensitive, so a small angular error becomes a lever-arm position error at the object [mine]. OK-Robot reports miscalibration over time (A26).
- Orientation (step 7): a single view sees only one side of the object (A27); normals from noisy depth are unreliable [mine].
- Tool model (step 9): a wrong TCP offset gives a systematic error [mine].
