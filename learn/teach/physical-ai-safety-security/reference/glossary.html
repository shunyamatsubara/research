Glossary

The words this course uses, with one meaning each. A term joins this list when a lesson teaches it. "Avoid" lists words that mean the same thing or that blur the meaning. Use the main term instead.

Core ideas

Physical AI
AI that senses the physical world and acts in it through a machine, such as a robot arm.Avoid: embodied AI (common in research; this course uses one name).
VLA (vision-language-action model)
An AI model that takes camera images and a language instruction and outputs robot actions. In the running example, the VLA performs the grasp.
Doer / checker
A design in which a complex part (the doer) does the work and a simple, independent part (the checker) watches it and can always force a safe state.Also called in research: monitor/actuator pair, Simplex architecture, runtime assurance. Avoid: "AI safety layer" (says nothing about independence).
Safety function
A function that protects people, whose failure would increase the risk of harm. Example: a protective stop.
Safety-rated
Designed and certified to a functional-safety standard, such as ISO 13849-1 or IEC 62061, for a stated reliability level.Avoid: "safe", "safety-grade" (marketing words with no stated level).
Performance level (PL)
The ISO 13849-1 grade for how reliably a safety function works, written with a letter, for example "PL d".
Safe state
A condition in which the machine cannot cause harm. It is not always "power off": a legged robot falls when its power is cut.Avoid: "off".
Semantic safety
Avoiding harm that comes from the meaning of a task, such as which object goes where, rather than from the motion itself.
Trust boundary
In this course: the line between L3 and L4. Below it, no safety function depends on the AI or on the computer the AI runs on.
Reference monitor
A security mechanism that is always invoked, tamperproof, and small enough to verify (NIST). In this course, the model for a good checker.

The five layers (course model)

The numbers follow the path of a motion command, from the request down to the moving steel. They are not a ranking.

L1 Check the task
Checks before the AI acts: is the request or plan safe and clear? Refuses it, or asks a person.
L2 The AI itself
The VLA and the motion planner, trained and tested to do the job well. The untrusted doer.
L3 Check the motion
Software checks between the AI and the robot (work area, speed and joint limits, collisions, stale sensor data), with a simple fallback. Not certified.
L4 Certified safety functions
Safety-rated functions that work without the AI and its computer: protective stop, speed and separation monitoring, power and force limiting, safety-rated zones, emergency stop.
L5 Physical design and procedures
Guards, a layout without pinch points, low-energy tools, training, and work rules such as stopping and locking the robot before maintenance.

Safety functions (L4)

Protective stop
A stop that a safety function triggers to protect people, for example when a person comes too close.Avoid: calling it an emergency stop; that is the manual button.
Emergency stop (e-stop)
A stop that a person triggers by hand in an emergency, usually with a red button.
Speed and separation monitoring (SSM)
Safety-rated sensors measure the distance between a person and the robot; the robot slows down and stops before they can touch.
Power and force limiting (PFL)
The robot is designed so that any contact with a person stays below set force limits for each body region.

Japan

Motion range (可動範囲)
Under the labour ministry (MHLW) notice for industrial robots: the maximum range the robot's parts, tool included, can structurally move. Only electrical or mechanical stoppers make it smaller.

Threat modeling (Lesson 2)

Entry point
A place where an attacker's input can enter the cell. This course uses eight (E1–E8); together they are the cell's attack surface.Avoid: "attack vector" (used loosely for both places and techniques).
Attack chain
The steps from an entry point to harm. A good threat model names one control that breaks the chain early and one that still protects people at the end.Avoid: "kill chain" (the name of a specific military and IT model).
Scene injection
Instructions placed in the camera's view, such as a sign or a printed patch, that steer an AI model.Also called: physical or environmental prompt injection.
Robot jailbreak
Prompts that make an LLM-controlled robot do what its rules should refuse.
Policy backdoor
Hidden behavior trained into a model that appears only when a trigger is present. Code review and normal tests do not reveal it.
Policy server
The computer that runs the VLA model and sends actions back to the robot over the network.
ROS 2 / DDS
ROS 2 is a common software framework for robots. DDS is the publish/subscribe middleware that most ROS 2 systems use to pass messages between nodes.
SROS2
The ROS 2 tools that switch on DDS security (authentication, encryption, access control) for groups of nodes. Security is off by default.
Zone and conduit (IEC 62443)
A zone is a group of systems that share common security requirements. A conduit is the controlled communication path between zones.
Wormable
Able to spread from device to device on its own, as UniPwn did over Bluetooth.

The eight entry points (course model)

E1 The scene
What the camera sees: parts, signs, people. An input that no firewall sees.
E2 Commands
Instructions from people or systems, for example through a chat window or an HMI.
E3 Models and data
Model weights, datasets and demonstrations, and the files and tools that load them.
E4 Policy server link
The network connection between the robot and the computer that runs the VLA.
E5 Robot middleware
ROS 2 / DDS and the other paths that carry messages between the robot's software nodes.
E6 Wireless setup
Bluetooth, Wi-Fi and other radios used to set up or control the robot nearby.
E7 Cloud, fleet and remote access
Vendor support, remote operation, updates and telemetry that cross the cell's boundary.
E8 The safety functions
The safety controller's settings and signals. The most valuable asset, because they are the last line.

Permissions and motion range (Lesson 3)

Permission (for the AI)
What the AI may ask the robot to do: which tasks, objects, places and actions. Enforced outside the model.
Default-deny
Allow only the actions the job needs, and refuse everything else.
Root-of-trust guardrail
A checker that user prompts cannot reach, which turns written rules into checks on every plan. RoboGuard calls its version a "root-of-trust LLM".
Motion limit
A limit on where and how fast the arm may move: software limits in L3, safety-rated limits in L4, stoppers in L5.
Monitored standstill
ISO 10218:2025's term for a standstill that a safety function watches while people work nearby.Avoid: "safety-rated monitored stop" (the older term).
Robot class (ISO 10218:2025)
Class I: manipulator mass ≤ 10 kg, force ≤ 50 N and speed ≤ 250 mm/s. Every other robot is Class II, which needs safety functions at PL d and SIL 2.
Collaborative application
An application designed and risk-assessed so that people and the robot can share space. Collaboration is a property of the application, not of the robot.Avoid: "collaborative robot" or "cobot" as if the label proved safety.
80 W rule (Japan)
A machine whose drive motors are all rated 80 W or less is outside the industrial-robot rules (Notice No. 51, 1983).
Fence-free routes (Japan)
The two 2013 routes to working next to a robot without a fence: a recorded risk assessment that shows no danger, or ISO 10218:2011 robots with a technical file and a declaration of conformity.
Teaching (教示等)
Programming or checking the arm's motions while inside its motion range. It needs written rules, a way to stop the robot at once, and special education.
Special education (特別教育)
Training the employer must give before workers do teaching or inspection work. For teaching: at least 7 hours of classroom and 3 hours of practice.

Data, models and know-how (Lesson 4)

Demonstration
A recorded example of a task, often made by teleoperation, used to train a policy. In a physical AI cell, demonstrations carry the operator's skill.
Trade secret (営業秘密)
Information that is managed as a secret, useful for business, and not publicly known (Unfair Competition Prevention Act, Art. 2(6)). All three conditions must hold.
Secret-management measures (秘密管理措置)
Steps that show employees the company intends to keep information secret, such as ㊙ marks, access limits and passwords.
Shared data with limited access (限定提供データ)
Data provided to specific parties as a business, accumulated in quantity and managed by electronic means (Art. 2(7)). A model trained on it may no longer count as the same data.
Derived model
A model made from an existing one, by additional training (再利用モデル) or by distillation (蒸留モデル). A contract must name these to restrict them.
Distillation
Training a new model on the inputs and outputs of an existing model.
Model extraction
Building a working copy of a model from its answers or its behavior, without its files. For robot policies it works like imitation learning.
Membership inference
Guessing whether a given record, or a whole demonstration, was in a model's training data.
Data poisoning
Changing training data so that the model learns a hidden or wrong behavior. In robots, a physical object in the scene can act as the trigger.
AIBOM (ML-BOM)
An inventory of the models, datasets and other parts of an AI system, next to the SBOM. Formats: CycloneDX ML-BOM and the SPDX 3.0 AI profile.
Model signing
A signature over a model's files that proves who made them and that they were not changed. It does not prove the model is safe.
Safetensors
A file format for model weights that cannot carry code, unlike pickle.

Camera data, remote operation and the cloud (Lesson 5)

Personal information (個人情報)
Information that can identify a living person, including camera images in which a person can be identified.
Personal data (個人データ)
Personal information in a database organized so that you can search for a person. Duties on security, third-party provision and transfers abroad attach to it.
Purpose of use (利用目的)
What the data is used for. In Japan it must be specified as far as possible and notified or published. AI training is a purpose to state.
Entrustment (委託)
A vendor handles personal data for your purpose. It may not use the data for its own purposes.
Transfer abroad (外国にある第三者への提供)
Giving personal data to a third party in another country (APPI Art. 28). It needs consent or an exception, even when the server is in Japan but a foreign company handles the data.
Specified biometric personal information (特定生体個人情報)
A new category in Japan's 2026 amendment for biometric data that can be collected cheaply, such as face features. Not yet in force.
Emotion recognition (EU)
AI that identifies or infers emotions or intentions from biometric data (AI Act Art. 3(39)). Banned at work and in education in the EU, except for medical or safety reasons (AI Act Art. 5(1)(f)). Pain and fatigue are not emotions under the Act.
Autonomous operation (自律運転)
The machine is in control in normal operation; people start it, watch it and stop it in an emergency (MHLW, 2026).
Remote operation (遠隔運転)
A person is in control in normal operation, from a distance (MHLW, 2026).
Cableless control
Control over radio or another link without a cable. On loss of the link the machine must stop automatically, and restoring the link must not restart it (IEC 60204-1, 9.2.4).
Jump host
A hardened server that is the only way in for remote users, where authentication and session recording happen.
Just-in-time access
Remote access that is opened only for an agreed time window, such as a maintenance slot, and closed afterwards.
Push-based architecture
The cell sends data out; nothing outside holds a standing connection into the cell.
Telemetry
Data a device sends to its maker or a service, such as state, logs or sensor readings. Ask what is sent, where and how often.

From PoC to production (Lesson 6)

Stage gate
A decision point between project stages, with evidence that must exist before the project moves on.
Operating conditions
The written conditions under which a system is claimed to be safe, such as objects, lighting and people's access.Also called: operational design domain (ODD).
Safety case
A structured argument, backed by evidence, that a system is acceptably safe for a stated use.
Fault injection
Testing by causing failures on purpose, to show that the safety functions really work.
95% upper bound
The highest failure rate still consistent with your test results at 95% confidence. After 50 failure-free trials it is about 5.8%.
Retraining trigger
The rule that a retrained model is a change, which needs an impact analysis and re-validation even when no code changes.

Reading vendor claims (Lesson 7)

First, second and third party
Who checked a claim: the vendor itself, a body that is part of the vendor, or an independent body.
Accreditation
Formal recognition that an inspection or certification body is competent to do its job, for example ANAB accrediting an inspection lab.Avoid: treating accreditation of a lab as certification of a product.
Readiness inspection
A check of whether a product is ready to be certified. It is not a certificate.
