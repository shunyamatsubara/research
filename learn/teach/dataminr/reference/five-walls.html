5 つの壁 早見表

routine（まとめ役）と Dataminr（警報役）のちがいを、自社サービスの設計に使える形でまとめた表です。

ひとことで

  • まとめ役（routine）：決まった時刻に起きて、検索して、読んで、書く。
  • 警報役（Dataminr）：流れを見張り続け、いつもとのずれを見つけ、関係する人にすぐ届ける。
  • Dataminr の中でも LLM は「見つけたあと」に使う（説明・裏づけ・背景）12。routine が再現できるのは、この後ろの部分。

壁ごとの比較

  1. 1速さいつ見るか
    routine

    最短 1 時間ごと。毎時ちょうどは数分遅れることも。API での起動は 1 つの routine につき 1 時間 30 回まで3。

    Dataminr

    届いたそばから処理。航空機の信号の例で「検知から配信まで 5 秒未満」（2019 年）4。

    自作の手常時動く小さな受信プログラムを別に置き、異変のときだけ routine を API で起こす。routine の公式文書も「監視ツールがしきい値を超えたら API で routine を起動する」使い方を例に挙げている3。

    設計の問い何分以内に知る必要があるか？

  2. 2視野何が見えるか
    routine

    検索エンジンに載ったものだけ。WebSearch が返すのはタイトルと URL5。X は Google と Bing 以外のクローラーを断っている6。

    Dataminr

    100 万以上の情報源、150 以上の言語、画像・音声・センサー7。Twitter（現 X）の全投稿へのアクセス（2016 年の資料8、2023 年の報道9）。

    自作の手開いたデータから始める。Bluesky の firehose は認証なしで使える10。GDELT は 15 分ごとに更新11。X の全投稿は Enterprise 契約のみで価格は非公開12。Reddit の API は事前の承認が必要で、商用利用には別の契約が要る13。

    設計の問い最初の兆しはどこに出るか？ そのデータを使う権利はあるか？

  3. 3規模どれだけ読めるか
    routine

    1 回の実行で数十ページ。X の投稿は API で 1 件 0.005 ドル、月 300 万件まで14。

    Dataminr

    50 以上の小さな専用モデル（言語・場所・固有名詞・OCR・ロゴ）で、入力の 95% 以上を落としてから大きなモデルへ1。

    自作の手キーワードや小さな分類モデルで先にふるい、LLM は急に増えたかたまりだけに使う。研究でも、専用に調整したモデルのほうが、調整なしの大きな LLM より分類が正確だった15。

    設計の問い1 日に何件読む必要があるか？ 1 件あたりいくらで読めるか？

  4. 4記憶何と比べるか
    routine

    実行ごとに新しいセッションで、リポジトリも毎回 clone しなおす3。残せるのは、ほぼ git に push したものだけ。

    Dataminr

    複数の時間幅で投稿をまとめ、移動平均などの基準とのずれで「高まり」「急な広がり」を判断する（2009 年出願の特許）16。続報は前のアラートにつながる17。

    自作の手件数の時系列を保存し、短い期間の平均と長い期間の平均を比べる。米国地質調査所がツイートから地震を見つけた方法と同じ考え方18。報告済みの出来事の一覧も持つ。

    設計の問い「いつも」をどう覚えるか？ 同じ出来事をどうまとめるか？

  5. 5選別誰に何を送るか
    routine

    その場の LLM の判断に頼る。AI アシスタントのニュースについての答えの 45% に重大な問題があった19。知らせるのは Slack などのコネクタ経由3。

    Dataminr

    位置情報つきの投稿は 2〜3%。残りの場所を推定（2016 年に最大約 60%）8。推定位置に誤差の半径17、拠点のまわりの smart radius20、人の専門家21、優先度は Flash・Urgent・Alert22。

    自作の手拠点・取引先・出張者の一覧を持ち、場所の推定と誤差を扱う。複数の情報源で裏づけ、送る前に人が確かめる段階を残す。

    設計の問い誰に・何を・どの急ぎで送るか？ 誤報をどう止めるか？

費用の試算（前提つき）

2026-10-15 時点の公式料金23をもとにした筆者の試算です。前提を変えると結果も変わります。

料金
Claude Haiku 5.5：入力 0.10 ドル、キャッシュ読み出し 0.01 ドル、出力 0.50 ドル（いずれも 100 万トークンあたり、プロンプト 10 万トークン以下）。Batch API は半額だが、結果は最大 24 時間後。
前提
投稿 1 件 75 トークン、指示文 600 トークン（キャッシュ）、出力 15 トークン、思考なし、1 件ずつ送る。
1 件あたり
75×0.10 + 600×0.01 + 15×0.50 = 21.0 → 0.000021 ドル
1,000 万件 / 日
約 210 ドル / 日（約 6,300 ドル / 月）。毎分約 6,944 件で、1 件 1 リクエストなら上位の利用枠が必要24。
1 億件 / 日
約 2,100 ドル / 日。
データの値段
X の投稿を API で 1,000 万件読むと 5 万ドル / 日。しかも月 300 万件の上限を超えるので、実際は Enterprise 契約が必要14。
結論
お金の壁は、モデルよりデータのほうがはるかに高い。
